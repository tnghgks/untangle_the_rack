# 전용 랙과 짝 연결 — 설계

- 작성: 2026-11-11
- 바탕: `docs/GDD-피벗-서버실-방치형.md`, ② 설계 `2026-11-10-rack-expansion-design.md` 26행("전용 랙 보너스 → ③")
- 세 작업 중 세 번째: ① 선 정리 (완료) → ② 새 랙 사기·랙끼리 잇기 (완료) → **③ 랙 테마와 장비 연결 규칙**

표기: **[사용자]** 사용자가 정함 · **[내 판단]** 내가 정하고 사용자에게 알림 · **[빌더]** 만드는 사람이 정해도 됨

## 1. 왜 만드나

서버를 사서 꽂을 때 "어디에, 무엇과 같이 둘까"를 고르는 재미를 더한다. 너무 현실적으로 가면 캐주얼하지 않으니 가볍게 **[사용자]**.

## 2. 원칙 · 하지 않을 것 · 실패로 볼 것

- 규칙은 **보너스로만** 작동한다. 안 지켜도 서버는 지금처럼 돌고 수익은 줄지 않는다 **[사용자 동의]**
- 새 장비·새 포트·새 케이블 종류 없음. 가격 안 바꿈 **[사용자 동의]**
- 저장 형식 안 바꿈 — 보너스는 배치·배선에서 매번 계산 **[내 판단]**
- 클러스터 보너스(전용 랙끼리 잇기)는 하지 않음 (② 설계 때 미룸)

**실패로 볼 것 [사용자]:** 심한 렉 · 직관적이지 않고 복잡함
→ 계산은 장비 수에 비례하는 단순 반복만 (매 프레임 돎). 메시·재질은 상태가 바뀔 때만 바꿈. 화면에 글씨를 늘리지 않고 색 띠와 짧은 반짝임으로 보여 줌.

## 3. 규칙

### 3.1 전용 랙
- 한 랙에 달린 서버(엔트리·웹·스토리지·GPU)가 **2대 이상이고 모두 같은 종류**면 그 랙은 그 종류의 전용 랙 **[내 판단: 최소 2대]**
- 스위치·PDU·매니저는 셈에서 빠짐. 서버가 켜졌는지·가동 중인지는 안 봄 (부팅 중 띠가 깜빡이지 않게) **[내 판단]**
- **꽉 찬 전용 랙**: 그 랙에 그 종류 서버를 하나 더 끼울 빈 자리가 없음 (`slots.firstFree(sizeU) === null`) **[내 판단: "빈 칸 0"보다 덜 깐깐하게 — GPU 4U는 42U를 딱 맞게 못 채움]**
- 보너스: 전용 **+10%**, 꽉 찬 전용 **+25%** (둘 중 하나만) **[내 판단, 보수적 첫 값]**

### 3.2 짝 연결
- GPU 서버의 랜 포트와 스토리지 서버의 랜 포트가 **케이블 하나로 직접** 이어져 있고 **둘 다 가동 중**이면 짝 **[사용자 동의]**
- 짝이면 두 서버 모두 **+15%** **[내 판단]**. 랙이 달라도 됨 (10m 선)
- 둘 다 랜 포트가 2개뿐이고, 가동하려면 하나는 스위치에 꽂혀야 하므로 짝은 자연히 하나씩. GPU↔GPU, 스토리지↔스토리지는 짝 아님

### 3.3 수익
- 가동 중인 서버 수익 = 기본 수익 × (1 + 전용 랙 보너스 + 짝 보너스). 더해서 곱함 (예: 꽉 찬 GPU 전용 랙 + 짝 = ×1.40)

## 4. 보이는 것

- **랙 테마 띠**: 랙 앞·뒤 위쪽 가로대에 얇은 색 띠. 종류별 색(엔트리 은색 · 웹 하늘 · 스토리지 주황 · GPU 보라). 전용이면 은은하게, 꽉 찬 전용이면 밝게. 전용 아니면 띠 없음 **[내 판단: 색은 빌더가 다듬어도 됨]**
- **생기는 순간**: 전용 랙이 되거나 꽉 찬 단계로 오르면, 짝이 생기면 → 그 자리(띠 / 두 서버의 이어진 랜 포트)에 반짝임 + 짧은 효과음. 글씨 없음 (묶기 연출과 같은 원칙). 불러오기 직후 이미 있는 것은 연출 없이 띠만
- **정보 카드**: 서버 수익 줄에 보너스를 붙임 — `수익 3.9원/초 (전용 랙 +10% · 짝 +15%)`. 짝이면 줄 하나 더: `짝: GPU 서버`
- **가이드 패널**: "보너스" 소제목에 두 줄 — 전용 랙, 짝 연결

## 5. 빌더가 정해도 되는 것
- 띠 두께·위치·밝기, 반짝임 크기, 효과음 높이 (playTie와 구별되게)
- 내부 함수 쪼개기 (계획서에 이름이 있으면 그 이름은 지킬 것)
